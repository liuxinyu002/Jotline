## 1. Project Overview

### 1.1 定位

> **项目随手记**——给多项目并行的前场实施交付人员的**"项目第二大脑"**：**随手记录，Agent 帮你整理，随用随取**。

本地优先的桌面端工具，核心体验是 **"用户只负责捕获，Agent 负责结构化"**：任何应用里按全局快捷键唤起**随手浮窗**（记 / 查 / 看），**看到什么截什么**、丢图、问一句、瞄一眼待办，不打断原工作；10 秒入库，随时可查，周报自动成稿。

### 1.2 核心亮点

**「看到什么，截什么」三键仪式**：`⌘⇧⌃4 截图 → ⌥Space 唤起 → ⌘V 粘贴`。这是一句可背诵的动词序列，是产品的全部入口心智，**在全产品统一复述**——浮窗空态、首次三步卡、托盘 tooltip、卡片通道标注行、设置页页脚，全部出现同一句话。聊天记录、报错弹窗、终端输出、配置页面，一切屏幕内容都是捕获对象；粘贴 / 拖拽 / 打字是更快更准的进阶路径。

支撑亮点：

- **统一捕获管线**：任何输入 = 原件 + 摘要 Markdown + 事件 + 待办，一张操作卡片承载确认
- **人只捕获、Agent 结构化**：对话式记录，卡片永不自动入库
- **本地优先**：客户现场弱网/断网可用（OCR 全离线），回公司自动同步
- **时间线 + 溯源**：所有信息可回答"何时、谁、从哪来"
- **待办中心**：散落在文本 / 文件 / 图片里的"要处理的事"汇聚为独立实体，逐条可溯源（含附件原图 + OCR 高亮解析行）
- **越用越准**：纠正沉淀为两层记忆（全局习惯 + 项目惯例），纠正一次即记住、下次生效，可查看、可删除

### 1.3 背景与问题

前场实施人员同时并行 2–5 个项目，信息碎片、异构、时效强（聊天截图、会议结论、需求变更、现场报错、账号信息）。现有方式全部失败于同一个原因——**要求人来做结构化**：

| 现有方式 | 失败原因 |
|---|---|
| 共享表格 | 结构先行，异构信息塞不进统一 schema |
| 在线文档 | 叙事流水账，检索靠 Ctrl+F 和记忆 |
| 微信群 | 即存即逝，翻记录 = 考古 |

### 1.4 目标用户

- 前场实施交付人员（实施顾问/交付工程师），常驻客户现场或远程支持
- 团队规模 ≤ 10 人，Mac 优先
- 大量沟通发生在微信群和会议中，重要信息以**屏幕内容为主**（聊天窗口、报错弹窗、监控大盘、配置界面）

### 1.5 设计原则

1. **本地优先，原件为真相源**：附件原图 / 原文件永不改写；OCR 文本与摘要 Markdown 是内容的**检索代理**；SQLite 索引可随时重建
2. **捕获与整理分离**：丢进收集即算记录成功，Agent 异步处理；**轻量随手操作进浮窗（记 / 查 / 看），深度整理留主窗**——浮窗与主窗共用工具层（Agent 即接口），不各自维护状态
3. **Agent 即接口**：Agent 能做的事 = UI 能做的事（工具层 = 领域 API），未来扩展必须走同一层，禁止旁路
4. **预置模板 + 完全可改**：不给用户空白冷启动
5. **事实 grounding**：Agent 产出附原文依据，周报数字来自本地取数；待办逐条可溯源（含附件原图）
6. **知情与选择**：云端/本地由用户配置，系统在卡片上**如实标注实际处理通道**

### 1.6 成功标准（功能验收制）

- **每个功能以"能用 / 不能用"验收**，不为评估专门筹备数据集；量化问题在使用中发现、在版本迭代中改进
- **北极星：捕获习惯是否成立**——这是最大产品风险，捕获不成立则全链路空转。缓解：本地埋点漏斗观察（人均捕获频次日均 ≥ 3 次为参考信号，非硬性闸门）、空态引导降低捕获心智门槛、三键仪式全产品复述、周报钩子反向激励
- 埋点仅本地记录，设置页可查看/导出/清除，不上传

## 2. In-Scope & Out-of-Scope

### 2.1 In-Scope（版本路线）

| 版本 | 范围 |
|---|---|
| **V1** | 随手浮窗（记 / 查 / 看）+ 统一内容解析（截图 OCR / 文本 / 文件，含投递聚合与时间锚行提取）+ 操作卡片 + 记忆机制 + 模板系统 + 时间线（阶段预设折叠 + group_name 分组）+ 检索 + 凭证库 + 待办中心基础版 |
| **V2** | 文件夹批量导入 + PDF/Office 解析器 + 长文本渐进渲染 + 周报生成 + 飞书实时转发捕获验证 + 待办批量来源接入（文件夹 / 图片解析） |
| **V3** | Hub 同步 + 经验沉淀 + 跨项目 RAG 问答 |

> **OCR 精度降级路径**：图片实测不可读时，V1 图片存原图进待处理队列，OCR 随 V2 补上，主流程不受影响；图片来源的待办同规则降级（待办先建，附件原图可看，OCR 高亮随 V2 补）。

### 2.2 Non-Goals（明确不做什么）

- 不做项目管理功能（甘特图、任务分派、进度跟踪）——这不是 PM 工具
- **不做群消息自动监听、不做 IM 聊天记录导入**——所有 IM 内容仅支持用户主动捕获（截图 / 粘贴 / 转发）；聊天记录的导出由用户自行解决，产品只处理捕获进来的内容，不对任何 IM 的格式变化负责（飞书主动转发见 §4.5）
- 不做会议实时转写/录音
- 不做模型微调——团队规模与数据量不支持，"越用越准"靠记忆机制实现（§4.2）
- 记忆不跨用户共享——V3 同步时全局记忆保持个人私有（项目层 V3 再议）
- **随手浮窗不承载批量 / 深度操作**——批量审查、三视图管理、周报编辑、凭证库管理页等留主窗，保持浮窗轻量速览
- **不做待办的协作指派 / 跨人分派**——待办是个人执行视图（V3 团队同步时再议）
- **不做聊天截图说话人自动归因**——布局启发式脆弱且收益低，说话人由用户在卡片审查时人工补充
- **不做时间线手工折叠组**——不要求用户手动点选事件建组；分组由 Agent 建议 `group_name`，用户确认
- **不建黄金集评估体系**——功能验收制 + 使用中改进（§1.6）
- V1 不做 Windows、移动端、多语言

### 2.3 Open Decisions（待定决策）

| 项 | 说明 |
|---|---|
| 待办状态机 | 仅"开放/完成"二态 vs 增加"进行中/已放弃"中间态；逾期提醒升级规则；V1 设计内定稿后写入 FR-17 |
| 日历视图版本归属 | 待办中心基础版随 V1；日历视图成本较低，倾向 V1，待拍板 |
| 浮窗凭证 list 项目过滤 | 当前按当前项目上下文展示；是否需要项目下拉切换，随浮窗「查」细化定 |
| DeepSeek 数据留存政策 | 设置页展示政策链接；云端标注如实呈现 |
| V3 设计前补齐 | tag 合并/重命名与模板编辑的跨端冲突方案；hub 成员认证与传输加密；待办是否纳入同步范围 |
| 其他行业阶段模板 | 机制已通用化，后续只补内容不动架构 |

## 3. Core Requirements

### 3.1 用户故事与验收标准

| # | 用户故事 | 验收标准 |
|---|---|---|
| US-1 | **As a** 实施顾问，**I want to** 在任何应用里把截图丢进随手浮窗后立即收起（Esc），**so that** 不打断正在处理的客户问题 | 丢入后 < 1s 可收起；解析完成托盘通知；未审卡片角标计数（托盘与浮窗「看」同步）；丢入即视为记录成功 |

| US-3 | **As a** 实施顾问，**I want to** 问"上次数据库连接问题怎么解决的"，**so that** 不用翻群记录考古 | 回答附原文引用与时间；工具调用 ≤ 5 次；浮窗「查」为轻量入口，深度检索回主窗 |
| US-4 | **As a** 交付工程师，**I want to** 存客户环境账号密码，**so that** 现场随时可取且不留明文 | 捕获含密码文本自动转凭证卡；笔记中仅占位符；查看密码需确认且仅进剪贴板；浮窗「查」可 list 凭证（仅名称/元数据，与主窗同源）；明文取用仅经「复制」按钮确认，浮窗触发同样落审计日志 |
| US-5 | **As a** 实施顾问，**I want to** 周五一键成稿周报，**so that** 不再回忆一周做了什么 | 草稿每个数字可溯源到本地事件；记录不足时顶部提示 |
| US-6 | **As a** 交付工程师，**I want to** 把聊天记录、截图、文件里"要我做的事"集中到一个页面逐条勾销，**so that** 会上答应的事都有下文 | 文本 / 文件 / 图片（OCR）解析的待办统一进待办中心；每条待办可溯源（来源卡片 / 纪要 / 附件原图 + OCR 原文高亮被解析行）；今日到期 / 逾期在托盘与浮窗「看」聚合计数；待办完成 / 逾期状态与时间线"事件只增不改"生命周期分离 |

## 4. Core Features

### 4.1 随手浮窗与对话式捕获（产品灵魂交互）

**随手浮窗（FR-1）是产品门面**：不切 App、不打断原工作，Esc 即回原工作。**截图是第一捕获路径**——"看到什么，截什么"覆盖聊天记录、报错弹窗、终端输出、配置页面等一切屏幕内容，粘贴/拖拽/打字作为更快更准的进阶路径。**三键仪式（⌘⇧⌃4 → ⌥Space → ⌘V）在空态、三步卡、托盘 tooltip、卡片标注行、设置页页脚统一复述。**

**三态定义**：

| 态 | 内容 | 边界 |
|---|---|---|
| **记** | 截图粘贴（⌘⇧⌃4 → ⌘V，剪贴板为图片时唤起自动进入投递预览）/ 随手记一句 / 粘贴文本 / 拖入文件与文件夹；连续多图 10s 窗口内归并为同一捕获单元（投递聚合，§4.4）；丢入 < 1s 可收起；浮窗内迷你进度（就绪后托盘 + 角标提醒） | **卡片永不自动入库** |
| **查** | 口语化问句（附原文引用 + 时间 + 来源）、快速搜索（含 OCR 文本命中）、凭证 list（与主窗同源，仅元数据，见 §4.9） | 工具调用 ≤ 5 次；深度检索 / 元数据筛选 / 批量操作回主窗 |
| **看** | 待审卡片就地执行 / 丢弃、今日待办勾销、最近时间线速览 | 批量审查 / 深度调整 / 三视图管理回主窗 |

**窗口行为**：默认落位**屏幕顶部居中**（Spotlight 式，远离底部任务栏 / Dock）；标题栏可拖拽（拖后记忆位置）；支持置顶钉住；托盘常驻，点击同效。

**快捷键体系**（默认值，设置页可改键）：⌥Space / ⌥Q 唤起 / 收起（双绑定）；⌥1 / ⌥2 / ⌥3 切换记 / 查 / 看；Enter 发送；Esc 收起（输入中先失焦；置顶钉住时不收起）。

**冷启动空态（记态，无任何捕获记录时）**：

```
        看到什么，截什么 ✦

  聊天记录、报错弹窗、配置页面——
  ⌘⇧⌃4 截图，回到这里 ⌘V 粘贴
  Agent 识别文字，提取事件和待办

  ────────────────────────
  纯文字直接打 · 文件直接拖 · 文本直接粘
```

首次唤起叠加三步卡（任意操作后消失）：`① 截屏 ⌘⇧⌃4 → ② 唤起 ⌥Space → ③ 粘贴 ⌘V`。有捕获记录后空态退化为单行：`拖入 / 粘贴 / 直接打字，Esc 收起`。「查」空态：`试试问："上次 Oracle 连接问题怎么解决的？"`；「看」空态：`没有待审卡片。随手截点什么试试 →`。

**状态同源**：浮窗不维护独立状态，三态全部读写走领域 API（工具层 = 领域 API，同一 SQLite / 文件真相源），待审卡片、待办、时间线与主窗实时一致——浮窗三态操作与主窗结果一致由架构保证（§7.4 说明 7）。

**记态主流程（对话式捕获）**：

```
⌥Space / ⌥Q / 托盘 → 随手浮窗（默认落位屏幕顶部居中）
 → [记] 截图粘贴（⌘⇧⌃4 → ⌘V）/ 随手记一句 / 拖入文件 / 粘贴文本
 → 连续多图 10s 窗口归并为同一捕获单元（投递聚合）
 → [截图] 主进程 /api/ocr 提取文字（本地 OCR 引擎）→ 文字交主模型
 → [云端路径] 工具层脱敏闸门 → DeepSeek ｜ [敏感项目] Ollama 本地
 → Agent 产出操作卡片（摘要 Markdown + 事件 + 待办 + 项目/目录/标签/group_name 建议 + ☁/🔒 标注）
 → 丢入即可收起（Esc）→ 空闲时浮窗「看」或主窗审卡片
 → 用户对话调整（"放运维目录，加个 oracle 标签"）→ 卡片更新 + 纠正写入记忆
 → 审查时人工补充说话人等信息 → 点「执行」→ 入库（原件 + 笔记 + 索引 + 待办）+ 生成时间线事件
```

- 项目归属三层策略：默认最近活动项目 → Agent 基于内容 + 全局记忆推断覆盖（注明理由）→ 卡片一键改
- 异步处理：处理完成托盘提醒，卡片待审（浮窗「看」与托盘角标聚合同一计数）
- **通道标注**：卡片展示 `☁ deepseek-chat · 已脱敏` 或 `🔒 本地模型`，只陈述处理时实际使用的通道（读 provenance.processing，非设置页当前值），不可点击、无动作
- 每次纠正即时写入记忆（§4.2），纠正一次即记住、下次生效——浮窗与主窗发起的纠正同路由

### 4.2 Agent 记忆机制（"越用越准"的实现）

**定义**：同类输入第二次出现时，Agent 产出与用户意图的距离缩短，且缩短来自本地积累的、用户可查看可删除的记忆。

**定位**：记忆 = 用户当前偏好的本地账本。纠正一次 = 记住 = 下次生效——学习由真实纠正驱动，无生效门槛。卡片永不自动入库，记忆只影响 Agent 建议，错误记忆的代价 = 一次可一句话纠正的建议（且被下一次纠正自然覆盖），因此不设固化阈值、不设过期机制。

**两层结构**：

| 层 | 存储 | 内容 | 解决什么 |
|---|---|---|---|
| 全局层 | `memory/global.json` | 跨项目习惯：内容→项目归属、人物称呼映射、客户术语、个人风格偏好、全局标签黑名单 | 项目推断依据；跨项目一致习惯 |
| 项目层 | `projects/<prj>/memory.json` | 该项目惯例：目录归属、项目术语、标签偏好、项目级黑名单 | 项目差异化惯例 |

记忆条目为自然语言单句（如"Oracle 相关的内容都归 AMS 项目"），以用户纠正原话为素材，人读得懂、模型用得上。

**写入时机（唯一触发点 = 卡片执行落库）**：

| 场景 | 行为 |
|---|---|
| 落库时 Agent 初始建议 ≠ 最终执行 | 写入/更新对应层记忆，下次同类场景即生效 |
| 落库时无差异 | 不写（一次说对 = 零成本） |
| 对话调整过程中 | 只更新卡片，不写记忆（改草稿非定论） |
| 用户明说"以后都这样" | 立即写入为显式规则，永不自动失效 |

- 写入层归属：跨项目习惯 → 全局层；项目相关惯例 → 项目层
- 纠正来源不区分入口：浮窗「看」态执行前调整与主窗对话调整同路由写入
- 写入失败静默：不提示、不阻塞捕获，下次纠正自然重写

**使用**：

- 记（卡片生成）与查（问答）均注入全部记忆：查态借助人物称呼与客户术语（"蓝屏" = CRM 登录报错）把口语化问句翻译为可检索内容，支撑检索命中率
- 命中透明：卡片建议注明"按你的习惯"，无引用追踪
- 标签黑名单双保险：prompt 注入引导 + 落库前确定性过滤，黑名单标签不会出现在任何卡片建议中

**管理**：「Agent 记住了什么」设置页：逐条人话展示，可编辑、可删除；保险丝定位，不进任何主工作流。

**规则**：

- 冷启动：项目层为空时，模板供结构、全局层供路由（"默认最近活动项目"即全局层原始形态）
- 项目结项：项目层记忆归档；同模板新建项目时可导出为种子（实施项目高度相似，种子价值高）；全局层不设过期，过时偏好被下一次纠正直接覆盖
- V2 增强：已执行卡片作为"输入→正确输出"正样本，FTS 按标题+标签检索相似历史卡片注入 few-shot（无需向量检索）——few-shot 为示例通道，与记忆（规则通道）相互独立
- V3 伏笔：项目层记忆可随 hub 在项目成员间共享（届时再议），全局层保持个人私有
- 存储：JSON 文件为真相源，SQLite 索引可重建

### 4.3 三视图信息组织

| 维度 | 职责 | 规则 |
|---|---|---|
| 目录 | 主分类，回答"放哪" | 单一归属，仿文件系统 |
| 标签 | 多维属性，回答"是什么" | 全局池、多归属、支持重命名/合并、Agent 优先复用已有标签 |
| 时间线 | 时序视图，回答"何时/谁" | 事件只增不改（纠错走作废 + 重建，FR-4）；折叠见下 |

**时间线折叠**：

| 层 | 规则 |
|---|---|
| 基础层 | 按阶段 / 项目周期折叠（模板预设，零手工） |
| group_name 层 | 按 Event.group_name 分组折叠；Agent 在卡片确认时建议（"这是上次系统升级的后续事件"），用户可改；无组事件不折叠 |

Markdown 策略：知识类内容全文 Markdown；正式文档（Word/PDF/Excel）原文保真 + Agent 生成 Markdown 摘要卡片；图片存原图 + OCR 文本入索引——**原件为真相源，摘要与 OCR 文本为检索代理**，此策略统一适用于全部捕获类型（§4.4）。

### 4.4 内容解析与结构化提取（统一捕获管线，FR-8）

**核心原则**：任何输入 = **原件（如有）+ 一份摘要 Markdown + 若干已发生事件 + 若干未来待办**，全部由一张操作卡片承载确认。记录功能是唯一入口；聊天记录导出由用户自行解决（截图 / 粘贴 / 任意方式），产品只处理捕获进来的内容。

**管线**：

```
任何输入（文本粘贴 / 图片 / 拖拽文件）
 → [确定性预处理，主进程] 图片→/api/ocr｜文件→存储+SHA-256 去重｜文本→直通
 → [Agent 结构化] 摘要 Markdown + 事件[] + 待办[] + 项目/目录/标签/group_name 建议
 → [操作卡片] 确认 → 入库（原件 + 笔记 + 索引 + 待办 + 时间线事件）
```

**输入类型行为矩阵**：

| 输入 | 原件 | 摘要 Markdown | 事件 / 待办提取 |
|---|---|---|---|
| 文本粘贴 | 短文本即正文；长文本（>8K 字符）存原文附件 | 笔记正文即摘要 | 从文本提取 |
| 图片 | 原图入附件库 | **OCR 全文 + Agent 摘要**（摘要引用 OCR 行） | 从 OCR 文本提取；待办带 bbox 行级溯源（§4.11 高亮）；说话人由用户审查时人工补充 |
| 文件 | 原文件存储 + SHA-256 去重 | V1：元数据卡（名称/类型/来源/大小）+ 可读文本摘要；V2：PDF/Office 文本提取后真摘要 | V1 从文件名/元数据；V2 起从提取文本 |
| 多文件 / 连续多图 | 各自存储 | 一张卡 N entries + 一份汇总笔记 | 各自提取 |

**提取规则**：

- **已发生 → Event**：线索 = 时间指称（昨天/上周五/3月12日）+ 事实性陈述（开了会/已上线/报错/已确认）；事件在摘要中保留原文引用句（grounding 不放松）
- **未来 → Todo**：线索 = "需要/记得/跟进/周X前" + 责任人 + 截止；due_at 解析失败置 null（进卡片墙不进日历，不猜日期）
- **宁缺勿滥**：低置信度条目不结构化，留在摘要正文；用户可手动转事件/待办（手动创建为 V1 既有能力）
- **时间锚行规则提取**：OCR 文本中的时间分隔行（`昨天 14:30` / `星期二 09:12` 正则）识别为会话时间锚点，喂给时间回退链 ①——这是纯规则提取，不做说话人归因、不做气泡布局推断

**时间取值回退链（适用于全部内容，导入/捕获一视同仁）**：

```
① 内容明示时间 → ② 内容可推导（"昨天"相对当天）→ ③ 捕获时间（capture_time）
凡 at ≠ capture_time，at_source 必填（content_time / derived_time）；
卡片标注来源且用户可改；待办 due_at 同规则
```

**投递聚合**：10s 窗口内连续多图归并为同一捕获单元 → 单卡片；OCR 行流按投递顺序拼接（相邻图重叠区去重）；卡片标注"N 张截图 · 已按顺序合并"。

**关键字段核验**：§4.9 秘密形态正则（报错码/路径/token/密码）复用于 OCR 关键字段校验；置信度低于阈值时摘要标注 `⚠ 请对照原图核对`；原图永远可查看（真相源），OCR 文本仅为检索代理。

**长文本策略**（用户把长对话/长文档直接粘进浮窗）：

| 项 | V1 | V2 |
|---|---|---|
| 触发 | >8K 字符或检出多消息结构 | 同左 |
| 处理 | 分块（~4K/块）逐块提取 → 合并 → 单卡片多 entries（card.batch，§7.3） | 渐进卡片：首块完成即出摘要，事件/待办追加渲染 |
| 降级 | 超时降级原文入库进待处理队列（§7.4 说明 6） | 同左 |

### 4.9 凭证库与工具箱

**存储（跨平台）**：

- 凭证存独立加密库（SQLCipher 或 libsodium 加密文件）；主密钥经 **keyring 抽象**存 OS 级凭证存储（macOS Keychain / Windows Credential Manager，同一接口）
- 必须提供**主密码恢复路径**（否则换机即灾难）
- 模型：`Credential { id, project, name, username, secret_enc, url, tags, updated_at }`

**引用与展示**：笔记中只出现占位符，UI 渲染为「🔒 UAT 数据库密码 [复制]」；模板"账号与凭证"目录仅存放占位符说明与入口。

**Agent 双约束（写死在工具层，主窗与浮窗一致生效）**：

- `list_credentials` 只返回名称/元数据，**永不返回明文**（防密码写进周报）
- `reveal_credential` 需用户**按钮显式确认**；输出**只进剪贴板，不进上下文、不进任何 note**；本地记录审计日志（append-only，不可清除）

**浮窗「查」开放 list**：

- 浮窗「查」与主窗**共用同一 `list_credentials` 工具**：只返回名称 / 元数据（名称、账号、主机、url），secret 字段永不返回
- 明文取用仅经「复制」按钮 → 行内显式确认 → **只进剪贴板**（不进对话、不进上下文、不进任何笔记）
- **浮窗触发的 reveal 同样落本地审计日志**，来源标注「随手浮窗」；主窗与浮窗审计汇聚同一日志
- 浮窗 list 的项目过滤口径见 §2.3 待定决策

**审计范围（V1 定稿）**：仅两类动作落审计——① `reveal_credential`（明文流出不留数据痕迹，必须留痕；浮窗触发来源标注「随手浮窗」，主窗与浮窗汇聚同一日志）；② 项目敏感开关变更（隐私通道的追溯锚点，记录变更前后值）。其余操作的追溯由 provenance、版本链、事件作废标记等数据结构承载，审计不双写。审计记录 append-only、不可清除（与行为埋点「可查看/导出/清除」严格区分），审计写入失败则拒绝本次取用（fail-closed）；存储与 schema 见技术规范书 §5.2。

**捕获联动**：正则检测到凭证形态（密码/密钥/token）→ 卡片 action 自动从 `create_note` 改为 `save_credential`，原文该段替换为占位符；同一检测结果驱动云端路径的出站脱敏兜底，**并用于 OCR 关键字段置信校验（§4.4）**。

**通用工具**：密码生成器等内置小工具。

### 4.10 检索与问答

**方案**：Agentic 检索（`search_content` → `read_file` → 归纳），V1–V3 **不建向量 RAG 层**；V3 如引入语义索引，只换 `search_content` 实现不换接口。

**接口承诺**：`search_content(query, filters, top_k) → [{id, title, snippet, provenance, score}]`，带 provenance 的结果列表，UI 与 Agent 共用。

**分层入口**：

- **浮窗「查」= 轻量入口**：单问句附引用作答 + 关键词快速搜索命中列表（含 OCR 文本命中）；不承载多轮深度检索
- **主窗 = 深度入口**：全文检索 + 元数据过滤 + `Cmd+P` 切换器 + Agent 多轮问答
- 两层**共用 `search_content` 接口**，结果一致

**检索 SOP**：Agent 优先读 Markdown 摘要卡，再决定是否读原文（零成本的检索增强）。

**预算**：问答 ≤ ¥0.1/次；工具调用 ≤ 5 次，超限基于已有结果作答并明确说明信息缺口。

### 4.11 待办中心

**定位**：待办是**独立实体**（"活数据"），不是时间线事件类型，也不是纪要里的普通一行——散落在文本、文件、图片里的"要处理的事"统一进独立功能页管理。

| 维度 | 规则 |
|---|---|
| 来源 | ① 操作卡片 Markdown 待办行（V1，Agent 解析，见 §7.3）；② 手动创建（V1）；③ 文件夹（PDF/Office 文本提取）/ 图片（OCR）批量解析（V2，随 FR-9 批量审查确认） |
| 生命周期 | 开放 → 完成（可恢复）；逾期 = due_at 已过且未完成；**与"事件只增不改"严格分离**：待办完成不回写时间线事件，两套生命周期互不污染；状态机细化见 §2.3 待定决策 |
| 页面结构 | 进行中卡片墙（今日到期高亮主卡 + 分类小卡 + 行卡）+ 日历视图（按到期日分布，点日期查看当日清单）；统计行：进行中 / 今日到期 / 已完成 / 逾期 |
| 溯源 | 每条待办带来源徽章（卡片 / 纪要 / 导入批次 / 手动），可回跳来源；**图片附件可查看原图 + OCR 原文，高亮被解析成待办的那一行**（原图为真相源，OCR 文本入索引） |
| 提醒 | 今日到期 + 逾期在托盘与浮窗「看」聚合计数；提醒开关 |
| 埋点 | 完成 / 逾期行为仅本地记录（FR-13），设置页可查看/导出/清除 |

**边界**：不做协作指派 / 跨人分派（§2.2）；owner 字段为记录用途（"谁负责"，来自解析上下文），不产生通知给他人。

## 5. App / User Flow

### 5.1 主流程：随手浮窗 + 对话式捕获

```
全局快捷键 ⌥Space/⌥Q / 托盘 → 随手浮窗（默认落位屏幕顶部居中）
 → [记] 截图粘贴（⌘⇧⌃4 → ⌘V，剪贴板为图片时自动预览）
        / 随手记一句 / 拖入文件 / 粘贴文本
 → 连续多图 10s 窗口归并为同一捕获单元（投递聚合）
 → [截图] 主进程 /api/ocr 提取文字（本地 OCR 引擎）→ 文字交主模型
 → [云端路径] 工具层脱敏闸门 → DeepSeek ｜ [敏感项目] Ollama 本地
 → Agent 产出操作卡片（摘要 Markdown + 事件 + 待办 + 项目/目录/标签/group_name 建议 + ☁/🔒 标注）
 → 丢入即可收起（Esc）→ 空闲时浮窗「看」或主窗审卡片
 → 用户对话调整（"放运维目录，加个 oracle 标签"）→ 卡片更新 + 纠正写入记忆
 → 审查时人工补充说话人等信息 → 点「执行」→ 入库 + 生成时间线事件
```

### 5.2 异步路径

```
丢入即收起（Esc）→ 后台解析 → 托盘角标 + 浮窗「看」徽标提醒
 → 空闲时点开审卡片（浮窗就地执行/丢弃，或主窗深度审查）
```

**卡片积压策略**：待审卡片在角标聚合计数（托盘与浮窗同步）；超 7 天未处理提醒一次；卡片永不自动入库，丢弃与执行均由用户决定。

### 5.3 查询流程

```
浮窗「查」（⌥Space → ⌥2）：轻量问句 / 快速搜索 / 凭证 list
或主窗：Cmd+P 切换器 / 全文检索（含 OCR 文本）/ 直接问 Agent
 → search_content（优先读摘要卡）→ read_file → 附原文引用回答
 → 工具调用 ≤ 5 次，超限基于已有结果作答并说明缺口
 → 深度检索 / 元数据筛选 / 批量操作回主窗
```

### 5.4 统一解析流程（FR-8）

```
任何输入 → 确定性预处理（图片→/api/ocr ｜ 文件→存储+SHA-256 去重 ｜ 文本→直通）
 → Agent 结构化（摘要 Markdown + 事件[] + 待办[]）→ 操作卡片 → 确认 → 入库

长文本（>8K 字符）：分块（~4K）逐块提取 → 合并 → 单卡片多 entries
                    （超时降级原文入库进待处理队列）

连续截图（10s 窗口）：归并单卡 → OCR 行流拼接 + 重叠区去重 → 整体解析
时间取值：① 内容明示 → ② 内容可推导 → ③ 捕获时间（at_source 必填、可改）
```

### 5.5 周报流程

```
选模板（个人/项目）→ 本地时间线取数 + 待办中心未完成/逾期项 → DeepSeek 按章节成稿
 → 草稿编辑 → 复制 Markdown
```

### 5.6 团队同步（V3）

```
指定 hub 机器 → 成员端按项目成员制同步
 → 事件只增不改 + 文件版本链 → 冲突后写胜出 + 保留副本
```

### 7.1 系统架构

```
┌─ Tauri 应用───────────────────────────────┐
│  Webview 前端 UI（主窗 + 随手浮窗多窗口）   │
│   · 随手浮窗 = 独立 Webview 窗口           │

│       同一主进程、Sidecar 与领域 API，      │
│       不新增服务、不双写状态                │
│      ↕ localhost HTTP + SSE（流式）        │
│  Rust 主进程：SQLite、文件操作、托盘、      │
│    全局快捷键、通知、凭证库（加密）、记忆索引│
│    ┌ OCR 服务（主进程内，接口化）           │
│    │  POST /api/ocr        单图同步        │
│    │  POST /api/ocr/jobs   批量任务        │
│    │    （并发 2–4、失败重试、断点续跑、     │
│    │     优先级队列：浮窗单图 > 后台批量）   │
│    │  引擎：  RapidOCR ONNX（Rust ort 加载） │
│    └─ 返回 lines[{text, confidence,        │
│         bbox, reading_order}] + 引擎/版本   │
│      ↕ stdio / HTTP                       │
│  Node Sidecar：pi agent（Bun 编译单文件，  │
│    纯 JS，无原生 addon）                   │
│    - provider 层：DeepSeek / Ollama       │
│      └─ ⚠️ 出站脱敏闸门：云端路径强制经过    │
│         （凭证库精确匹配 + 秘密模式正则，    │
│           确定性函数，位于工具层出口）        │
│    - Tools → 调用主进程暴露的领域 API       │
│    - OCR → HTTP 调用主进程 /api/ocr        │
└───────────────────────────────────────────┘
```

脱敏发生在工具层出口（确定性、可测试），不在 prompt 层。凭证精确匹配数据经领域 API 从主进程凭证库读取。OCR bbox 服务待办溯源高亮（§4.11）。OCR 文本若走云端路径，照常过 provider 出口的脱敏闸门。

| Tag | 全局池、使用计数、支持合并 |

### 7.3 操作卡片（关键组件，预留批量容器与项目字段）

```json
{
  "type": "card.batch",
  "project": "prj_ams",
  "confidence": "high",
  "reason": "内容提及 AMS 系统 UAT 环境",
  "entries": [{
    "action": "create_note | save_file | add_event | save_credential",
    "title": "UAT 环境数据库连接问题处理",
    "target_dir": "问题与变更/",
    "format": "markdown",
    "tags": ["环境", "数据"],
    "group_name": "UAT 环境搭建",
    "event": { "type": "问题", "stage": "测试验证", "at": "2025-06-12 14:30", "at_source": "content_time" },
    "todos": [{ "title": "部署手册补充「监听自检」步骤", "due": null, "owner": null }],
    "provenance": {
      "source": "paste | screenshot | file",
      "origin": "微信群-客户群 / 截图 ×3",
      "imported": false,
      "processing": { "model": "deepseek-chat", "cloud": true, "redacted": true }
    },
    "body": "## 现象\n…"
  }]
}
```

- `processing` 为执行时写入的事实数据：标注 UI 读取此字段而非设置页当前值，保证"设置变更后历史卡片标注不变"
- `todos[]`：Agent 从内容解析的待办；执行时创建 Todo 实体进待办中心（FR-17），原文待办行保留
- `at_source`：时间戳取值来源，Agent 推断时间时必填（§4.4 回退链）
- `group_name`：Agent 识别系列事件时建议填入（如"UAT 环境搭建"），用户可改；执行时写入 Event
- `origin`：截图投递聚合时标注"截图 ×N · 已按顺序合并"

### 7.4 关键架构说明

1. **pi 跑 sidecar 的原因**：pi 为 TS 生态，无法直接运行在 Tauri Rust 主进程中；Bun 编译 + externalBin 是标准解法。
2. **DeepSeek 无视觉能力与 OCR-only 方案闭环**：图片先经主进程 `/api/ocr` 转文字再交主模型，两个决策互相成全。
3. **OCR 与 Agent 解耦**：OCR 位于 Rust 主进程，sidecar 仅经 HTTP 调用 `/api/ocr`——sidecar 保持纯 JS，Bun × onnxruntime-node 原生 addon 兼容风险消除；接口返回带 bbox 的行流，服务待办高亮与规则提取（时间锚行）。
4. **工具层 = 领域 API**：`list_projects / search_content / create_note / save_file / upsert_tags / add_timeline_event / read_file / list_credentials / reveal_credential / upsert_todo` 等，UI 与 Agent 共用；未来扩展必须经此层，自动继承 grounding、provenance、脱敏闸门，禁止旁路。
5. **出站脱敏闸门**：云端路径的确定性函数（凭证库精确匹配 + 秘密模式正则），位于工具层出口；本地路径不脱敏（不出机，保真）。
6. **卡片 JSON 输出可靠性回路**：DeepSeek JSON Schema 校验失败 → 自动修复重试 1 次 → 仍失败降级为原文入库进待处理队列（不阻塞捕获，符合"丢入即成功"原则）。
7. **浮窗状态同源**：浮窗与主窗不各自维护状态，三态全部读写走领域 API（同一 SQLite / 文件真相源）——"浮窗三态操作与主窗结果一致"由架构保证，而非逐功能对齐。
8. **快捷键跨平台注意**：macOS 下 Option + 数字经 `e.key` 返回特殊字符（¡™£ 等），浮窗切态判定必须用 `e.code`；Windows 下 ⌥Space 存在系统菜单 / 输入法冲突风险，故默认双绑定 ⌥Q，设置页可改键，发布前实测。

| 成本 | 单次归档 < ¥0.01；Agent 问答 < ¥0.1/次；千文件级导入 < ¥10；单次长文本深度解析 < ¥0.5 |

| 前端 | **React** | 团队熟悉栈优先；浮窗与主窗同一前端工程、共用组件与状态层 |
| Agent 框架 | **pi agent**（Node sidecar） | Bun 编译单可执行（纯 JS，无原生 addon），Tauri `externalBin` 打包，用户免装 Node；扩展走领域 API 层 |
| 主模型 | **DeepSeek deepseek-chat** | OpenAI 兼容端点；操作卡片用 JSON Schema 约束输出 |
| 本地模型 | Ollama | 敏感项目专用（默认），全链路不出本机 |
| OCR | **macOS：Vision（系统原生）；Windows 适配期：RapidOCR ONNX（Rust `ort` 加载）** | 平台默认引擎唯一化，统一经主进程 `/api/ocr` 接口暴露（选型理由：Vision 系统自带、零模型分发，为 Mac 首选；RapidOCR 约 10–20MB 随包分发保障跨平台一致；OCR 文本并入全文索引；bbox 支撑待办高亮；sidecar 经 HTTP 调用） |
| 存储 | 本地文件夹 + SQLite（FTS5） | 文件为真相源，库可重建 |
| 凭证 | **OS 凭证存储（keyring 抽象）+ SQLCipher/libsodium 加密库** | macOS Keychain / Windows Credential Manager 同一接口；主密码恢复路径 |
| 系统集成 | tauri-plugin-global-shortcut / tray / notification / updater | **全局快捷键双绑定（⌥Space / ⌥Q，设置页可改键）**；浮窗窗口管理（always-on-top、顶部居中、拖拽记忆）；updater 签名密钥发布前配置 |
| 分发 | Developer ID 签名 + 公证 | 内部分发免"右键打开" |
| 同步（V3） | 同一二进制 hub 模式 | 局域网单中心，项目成员制；认证与加密 V3 设计前补齐（§2.3） |
