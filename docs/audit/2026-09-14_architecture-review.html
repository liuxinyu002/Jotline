§1 候选卡片（8）

候选 1 · 契约防线与 IDR-03 迁移边界对齐

Strong

涉及文件

scripts/pre-commit.sh · src-tauri/crates/server/src/bin/gen.rs · src-tauri/crates/server/src/lib.rs · src-tauri/crates/server/tests/

问题

同一根因的四道缝泄漏 / 无局部性：IDR-03 把 5 个 #[utoipa::path] 注解与 gen bin 迁入 server crate，但——① pre-commit 触发正则 ^(src-tauri/crates/contracts/|contracts/|scripts/|Cargo…) 不含 server，「内环秒级拦截」对契约源现在的物理位置失明（改 server 侧注解提交 → 漂移只能靠 CI 兜底）；② 全仓正确性最微妙的 Wire 纪律机械（strip_null 的 oneOf 坍缩与兄弟键提升、deref_refs 的 $ref 解引用 + 32 层防护）困在不可导入的 bin target 里，零单测——零漂移 diff 只证明「再生成 == 已提交」，不证明「变换语义正确」；③ 同一事实（端点 ↔ 注解）双注册：routes!() 与 ServerApiDoc 各手写一遍五条，且 split_for_parts() 已积累的文档半边被显式丢弃——漏登记 = 端点静默从契约消失，零漂移检查依然绿；④ 契约生成管线现在依赖整个 server 实现 crate 编译（axum / tokio full / rusqlite bundled），该构建耦合是 IDR-03 的内生代价，但无任何文档承认它。

方案（提案级）

  • pre-commit 触发正则补上 src-tauri/crates/server/（或收窄为注解所在 handler 文件 + gen bin）
  • 三个变换函数从 bin 移入 server lib（如 server::gendoc）+ fixture 单测（oneOf 坍缩 / 兄弟键覆盖 / 循环 $ref / 查询参数 required 修正），bin 只留 main() 装配
  • 加一条测试断言「路由表 path 集合 == ServerApiDoc path 集合」，把双注册纳入机器守卫
  • 在 design / IDR 登记构建耦合这笔已接受的账（不回迁注解——那与 IDR-03 矛盾）

收益（局部性 × 杠杆）

契约防线重新覆盖注解的真实住址（局部性回归）；「发布后契约变更属 breaking」这一承诺的执行机构（变换机械 + 注册守卫）从无守卫状态进入测试网——一处改动，三道防线同时闭合。

候选 2 · Mock 契约保真收口：响应侧校验 + 生成类型消费

Strong

涉及文件

contracts/mock/src/state.ts · contracts/mock/src/ajv.ts · contracts/mock/src/router.ts · contracts/mock/package.json

问题

Mock 的契约校验面只覆盖入口（请求体 / 查询参数 / 场景种子），响应侧零校验——而缝上已经漏出两处实际违约（父代理已复核源码）：① state.ts upsertEntity 更新路径 Object.assign(existing, {…body, id: undefined, created_at: undefined}) 后只恢复 id——created_at 留 undefined，JSON.stringify 丢键，PATCH 后的 stage/tag 及后续 list 响应缺必填字段（注释「id / created_at 不被覆盖」与实现相反）；② executeCard 中 note_id: noteIds.at(-1)——entry 只含 event 不含 create_note 时，事件挂到前一个 entry 的笔记。同时 Mock 是唯一不依赖 @jotline/contracts 的 TS 端，实体形状在手写镜像里四重存在（Rust 契约源 → openapi.json → schema.d.ts / state.ts 镜像 / 场景 JSON），契约加必填字段时 mock 的编译期与运行期都看不见。

方案（提案级）

  • 修复两处实际违约（解构剔除替代 undefined 赋值；event.note_id 仅在本 entry 创建笔记时关联）
  • 响应侧加 Ajv 校验（dev 断言模式：dispatch 后校验 result.body 对契约 schema，违约启动即红）
  • mock 引入 workspace @jotline/contracts，手写镜像改为引用 / satisfies 生成类型，契约变更在 mock 编译期可见

收益（局部性 × 杠杆）

「实体形状」的知识从四处收敛回契约单点（局部性）；一个校验点把 Mock 的静默漂移变成启动期红灯（杠杆）——Mock 是 Phase-11 前端连测的唯一替身，它的保真度就是契约测试的价值上限。

候选 3 · 前端异步失败路径修补（网络级异常不再卡死交互态）

Strong

涉及文件

app/src/App.tsx（三处调用点）

问题

openapi-fetch 对网络级异常（连接拒绝）是 rethrow 而非进 error 分支；App.tsx 三处 async 均无捕获（父代理已复核）：① handleSubmit await 抛错则 submitting 永久 true、按钮永久「保存中…」；② handleSearch 同理；③ useEffect 的 listProjects().then() 无 .catch——unhandled rejection，projectsError 永不触发，UI 静默（下拉禁用、无提示）。tasks 6.3 要求的失败状态只覆盖 HTTP 错误信封路径，不覆盖「服务器不可达」——这恰是 dev 常态（先开页面后起 server）。同一失败处理形态三处内联且漏同一路径（无局部性），但修补本身是三行级 try/finally/.catch，不是抽象问题——async triple 的统一形态按 phase-2 Non-Goal 留给 Phase-11。

方案（提案级）

三处各补捕获（handleSubmit / handleSearch 用 try-finally 复位交互态，useEffect 补 .catch 置 projectsError）；不引入任何抽象，不抽组件。

收益（局部性 × 杠杆）

切片验证骨架的失败矩阵补齐到「真实 dev 场景可达」——每个状态的失败路径都能被肉眼验证；为 Phase-11 抽象化提供正确的行为基线（先修对，再抽形）。

候选 5 · SSE 帧纪律等价性锚点

Worth exploring

涉及文件

contracts/mock/src/sse.ts · src-tauri/crates/server/src/stream.rs · scripts/mock-smoke.sh · app/src/use-note-stream.ts

问题

一个 wire 概念（SSE 帧）散落三端，契约只钳住 data 行的 JSON 形状：帧构造三处手写（sse.ts:41/60、stream.rs frame_event）；心跳间隔两处独立常量（15s 数值一致纯靠纪律）；event_id 单调性三套机制（Rust AtomicU64 / Mock SseHub.nextId / 剧本流字面值，场景校验不查单调唯一）；Last-Event-ID 三处均写了没人读；「SSE 端点识别」两套口径（Mock 按 operationId，Rust 按 path 字面量）。现有等价性锚点只有 mock-smoke 的一条 grep -c '^event:'。双实现本身成立（Mock 与 server 是真缝上的两个 adapter，各有真实调用方）——缺的不是合并，是可执行的等价性断言。

方案（提案级）

把帧纪律升为可执行断言：mock-smoke 补心跳行存在性与 event_id 单调性断言；或将样例帧做成三端共享测试向量（Rust 单测与 Mock 冒烟比对同一文件）。方案有取舍，需验证哪个锚点性价比最高。

收益（局部性 × 杠杆）

「Mock 与真实主进程行为等价」从一次性人工验证（phase-2 task 4.3）变成每次冒烟自动复验——多窗口同源是产品核心承诺，这条缝值得机器守卫。

候选 6 · 存储层 init 语义收口（Phase-3 前置输入）

Worth exploring

涉及文件

src-tauri/crates/server/src/storage.rs · src-tauri/crates/server/src/lib.rs

问题

三颗结构性引信（前两颗今天无害，属面向未来的登记）：① dev seed 无门控焊死在 Storage::init——design D4 措辞是「dev 首启 seed」，实现是「任何空库首启 seed」，ServerConfig 无 dev 标志，Phase-11 用户真实 vault 首启会得到假项目「切片示例」；② ADR-5 宣称「SQLite 仅索引、可随时重建」，但代码中不存在任何重建路径——删掉 index.sqlite 后既有笔记文件全部从 API 消失，无代码扫描文件回填；③ create_note 的崩溃窗口（文件已写、事务未提交时进程死亡）留下孤儿文件，init 不做对账——D9 只处理「事务失败」，没处理「进程死亡」。单文件六关注点本身已获 phase-2 Non-Goal 豁免，不作为问题。

方案（提案级）

seed 移出 init（独立 dev_seed() 由 bin / dev 编排调用，或 env 门控）；「索引重建 / 孤儿对账」作为 Phase-3 存储层重构的第一公民接口（如 reindex_from_files()），而非散在各 init 分支。门控机制需要决策（env 标志 vs 显式调用点）。

收益（局部性 × 杠杆）

init 的接口语义回到「调用方可推理」（不藏不可关闭的 dev 行为）；ADR-5 的「可重建」承诺获得实现锚点——这是 Phase-3 立存储架构时的现成设计前提清单。

§2 健康面（做对了的，值得保持）

· 依赖方向干净单向：server → contracts，无环；handler 直接用契约类型做 extractor/response，无 DTO 双份。

· contracts crate 是真缝：Rust / TS（app、sidecar）/ mock / 生成管线四侧真实调用方——「一个 adapter 的缝是假设性缝」的反面正面教材；define_id! 宏 15 个 newtype 一次成型，通过删除测试。

· SQL 完全收敛在 storage.rs：Connection 私有，handler 无任何绕过拼 SQL 的路径。

· tests/api.rs 是「接口可测」的正面样板：真实路由 + 真实存储（tempdir）+ oneshot 不占端口，零 mock；SSE 双订阅者同源有真实流断言。

· D9 双写边界三处互证：doc 注释 / 实现 / 测试一致，422/404 不留痕有断言；错误出口集中在 ApiError::into_response 单点。

· 契约确定性 + 零漂移是真杠杆：BTreeMap 全层键序、无时间戳，注解一处改动三产物联动；wire-grep.sh 把禁用清单机器化。

· sidecar 通道纪律双向守护：stdout 纯净性观测 + stderr NDJSON 解析转发，与 ADR-2/ADR-10 完全同构；boot 链超时降级不阻塞就绪。

· 场景按契约 Schema 启动校验、失败拒绝起服务、固定 ULID 可复述——契约保真的最强一环。

§3 首要推荐

先做候选 1（契约防线与 IDR-03 迁移边界对齐）。 理由：契约零漂移纪律是这个仓库的地基——phase-2 刚刚把五个注解和 gen bin 迁进 server，而内环防线（pre-commit）、变换机械（零单测）、注册守卫（双注册无断言）全部还站在迁移前的世界里。 这不是「未来会痛」的风险，是当下已在裸奔的缝：今天改一个 server 侧注解再提交，pre-commit 不会拦你。 修复全部是小时级、零行为变更的收口动作，且趁 phase-2 未归档、注解位置的记忆还新鲜时做，成本最低。 候选 2（Mock 保真收口）紧随其后——两处实际违约已在缝上漏出来，且它是 Phase-11 前端连测的价值上限。
