01

随手浮窗 · 记 / 查 / 看

场景：你在客户的远程会议里共享着屏幕——群里弹出关键信息。⌘⇧⌃4 一截，⌥Space 唤起浮窗，⌘V：整段对话连人带时间进了管线；Esc 一收，回到原工作。

查ASK

看PEEK

看到即截：聊天记录、报错弹窗、终端输出、配置页面——截图是唯一同时保住时间戳（画面内）+ 图片上下文 + 完整画面信息的入口；说话人等细节由你在卡片审查时一句话补充。
不打断：「丢入即可关窗」升级为「Esc 即回原工作」——捕获流不要求切走任何 App。
状态同源：浮窗与主窗共用工具层（Agent 即接口），操作结果一致率 100% 由架构保证（§6 说明 7）。
主窗做重活：深度审查、三视图、批量导入、周报、凭证与设置留主窗——捕获与整理分离。

通道标注 · 如实呈现

卡片标注读取的是执行时的事实（provenance.processing），不是设置页当前值。切一下开关感受差别：

敏感项目 · 本地模型

当前：云端 DeepSeek，出站强制脱敏。切到敏感项目后，同一条内容将全链路走本地 Ollama——不出机、不脱敏（保真）。

边界用例：项目后来才开敏感开关，历史卡片标注不变——标注与实际通道一致率目标 100%（§2.4）。
卡片就绪。推断依据已注明，你可以直接点「执行入库」，或者说句话让我改——下面是几个常用说法：
  1. ①项目推断附理由、可一键改——三层策略：默认最近活动 → 记忆推断覆盖 → 卡片一键改（§3.1）。
  2. ②一句话单轮理解：「放运维目录，加个 oracle 标签」即时更新卡片，无需学习表单（US-2 验收标准）。
  3. ③卡片里的 Markdown 待办行是待办实体来源之一 → 05 待办中心；事件行带 at_source 时间来源标注、可改（FR-8 回退链）。
  4. ④通道标注 ☁ / 🔒 只陈述事实、不可点击；设置变更后历史卡片不变（§4.4）。
03

Agent 记忆机制 · 越用越准

场景：同一个客户、同一类问题再次出现——这次 Agent 不再问，直接放对位置。纠正一次即记住、下次生效；「缩短的距离」来自本地可查、可删的记忆，而非模型微调。

    05

    待办中心 · 独立实体，独立页面

    场景：从文本、文件、图片（OCR）解析出的每一件「要处理的事」，都汇聚到同一个今日视图——点开任何一条，都能看到它的来源依据，包括那张现场拍的白板照片。浮窗「看」态可勾销，与此处实时同步。

    FR-17§3.13§3.4
    待办中心 · 今日视图 / 日历 · 全来源汇聚
    6月2025
    1. ①待办 = 独立实体（FR-17 已定案）：文本 / 文件 / 图片 OCR 均可产出；数据模型 Todo { id, project?, title, due_at, status, owner, source, attachments[] }。点「按白板照片…」的查看图片，可看附件原图 + OCR 原文 + 被解析成待办的那一行（bbox 行级溯源）。
    2. ②每条待办可溯源：来源徽章直跳卡片 / 纪要 / 粘贴捕获——事实 grounding 延伸到待办；日历视图按到期日分布（due 解析失败置 null，只进卡片墙不进日历，不猜日期）。
    3. ③待办是「活数据」（可完成、可逾期、可提醒），与「事件只增不改」的生命周期严格分离——待办不混入时间线事件类型。
    4. ④完成行为埋点仅本地记录（FR-13）；逾期 / 今日到期在托盘与浮窗「看」态聚合计数；不做协作指派 / 跨人分派（§1.7）。
    06

    问 Agent · 拒绝翻群考古

    场景：又遇到数据库连接问题。你不想回忆上次是谁说的、在哪个群——直接问一句，答案必须带原文、带时间、带来源。浮窗「查」是这里的轻量版；两层共用同一个 search_content 接口，结果一致。
